# 사용자 안내서 — 네이버 부동산 급매 주간 리포트

매주 화요일 오전 10시(한국 시간)에 등록한 아파트 단지의 매매 매물을 살펴보고,
급매로 보이는 매물을 정리한 리포트를 만들어 줍니다. 서버는 없고 Claude Routine이 대신 실행합니다
(설정은 [ROUTINE.md](ROUTINE.md)).

- 대상: 공급면적 36평(119㎡) 이하의 모든 평형, **매매** 매물
- 급매 기준(요약): 일반층(3층 이상) 매물이 최근 실거래 중앙값이나 다른 매물 최저가보다 **5% 이상** 싸면,
  저층(1·2층·지하) 매물은 **10% 이상** 싸면 급매로 봅니다.
- 결과: Routine 완료 알림(실행 요약)과 HTML 리포트 파일. 앱이 메일이나 메신저를 직접 보내지는 않습니다.

---

## 1. 단지 추가·삭제

조사할 단지는 저장소의 `config/complexes.yaml` 파일 한 곳에서 관리합니다.
GitHub 웹에서 파일을 열고 연필(편집) 아이콘을 눌러 고친 뒤 "Commit changes"로 저장하면 다음 실행부터 반영됩니다.

```yaml
complexes:
  - complex_no: "3009"
    name: 잠원동아
  - complex_no: "22627"
    name: 잠실엘스
```

### 단지 추가
1. 네이버 부동산(new.land.naver.com)에서 단지를 엽니다.
2. 주소창이 `https://new.land.naver.com/complexes/3009?...` 이면 `3009`가 단지 번호입니다.
3. 목록 끝에 두 줄을 추가합니다. 앞의 공백(스페이스 2칸, 4칸)을 위 예시와 똑같이 맞춥니다.
   ```yaml
     - complex_no: "12345"
       name: 우리동네아파트
   ```
   번호 대신 주소를 통째로 붙여 넣어도 됩니다: `- url: https://new.land.naver.com/complexes/12345`
   `name`은 알아보기 위한 메모입니다. 리포트에는 네이버의 실제 단지명이 나옵니다.

### 단지 삭제
해당 단지의 줄(`- complex_no:`부터 그 아래 들여쓴 줄까지)을 지웁니다.
지운 단지의 지난 급매 기록은 남아 있지만, 이후 리포트에는 나오지 않습니다.

### 자주 하는 실수
- 같은 단지를 두 번 적음, 목록을 비워 둠, 들여쓰기가 틀림 → 그 주 실행이 **설정 오류(FAILED)** 로 끝나고
  요약 첫 줄에 이유가 나옵니다. 파일을 고치면 다음 실행부터 정상입니다.
- 알 수 없는 항목 이름(예: `molit_seq` 오타)도 오류로 알려 줍니다.

## 2. "실거래 매칭 확인 필요" 처리

국토부 실거래 자료에는 네이버 단지 번호가 없어서, 단지마다 **국토부 단지 식별자(`molit_apt_seq`)** 를 한 번 정해 줘야 합니다.
정해지지 않은 단지는:
- 실거래 기준 없이 **매물끼리 비교한 결과로만** 급매를 판정합니다 (실거래보다 싼 급매는 못 찾습니다).
- 리포트의 단지 현황과 요약의 "확인 필요"에 **실거래 매칭 확인 필요**와 **후보 목록**이 나옵니다.

처리 방법:
1. 리포트에서 그 단지의 후보 표를 봅니다. 후보마다 식별자(`apt_seq`), 국토부 단지명, 법정동, 지번, 최근 거래 건수가 있습니다.
2. 네이버 단지 정보(주소·지번)와 같은 후보를 고릅니다. 애매하면 국토교통부 실거래가 공개시스템에서 단지명·지번을 확인합니다.
3. `config/complexes.yaml`의 그 단지에 한 줄을 추가합니다.
   ```yaml
     - complex_no: "3009"
       name: 잠원동아
       molit_apt_seq: "11650-123"
   ```
4. 다음 실행부터 실거래 기준이 함께 쓰입니다. 후보가 하나도 없거나 확신이 없으면 비워 두세요 (틀린 값을 넣는 것보다 낫습니다).

## 3. 수동 실행

### Routine에서
Routine 화면에서 이 Routine을 열고 "지금 실행"을 누릅니다. 결과는 정기 실행과 똑같이 `reports` 브랜치에 저장됩니다.

### 내 PC에서 (선택)
Python 3.12와 git이 필요합니다.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e .
cp .env.example .env        # 그다음 .env 파일을 메모장 등으로 열어 MOLIT_API_KEY= 뒤에 키를 붙여 넣습니다
```

- **연습 실행(드라이런)**: 기록을 바꾸지 않고 결과만 봅니다.
  ```bash
  .venv/bin/python -m app.pipeline --once --dry-run
  ```
  결과: `out/summary.md`(요약), `out/날짜.html`(리포트).
- **정식 실행 (Routine과 같은 방식, reports 브랜치에 저장)**:
  ```bash
  bash scripts/routine_run.sh
  ```
  Routine과 같은 주에 두 번 돌리면 이력이 두 번 쌓입니다. 보통은 드라이런만 쓰세요.

API 키는 `.env` 파일에만 넣고, 대화창·메일·저장소에는 붙여 넣지 마세요.
국토부 키가 없으면 실행은 되지만 실거래 기준이 빠지고, 결과가 **PARTIAL**로 표시됩니다.

## 4. 리포트·요약 읽는 법

### 실행 요약 (Routine 완료 알림)
첫 줄 예시:
```
[급매 리포트] 2026-10-13 (화) — 상태 OK · 신규 2 · 인하 1 · 지속 3 · 수집 실패 없음
```
- **상태**: `OK` 정상 / `PARTIAL` 일부 단지 수집 실패 / `FAILED` 수집 실패로 판정 못 함.
  앞에 `[수집 실패]`·`[수집 실패 있음]`이 붙으면 **"급매 없음"이 아닙니다.** 그 단지는 이번 주에 확인하지 못한 것입니다.
- **신규**: 이번에 처음 급매로 잡힌 매물. **인하**: 전에 알린 급매가 더 싸짐. **지속**: 지난번과 같은 가격으로 계속 급매.
- "이번 주 알림"에는 신규·가격 인하만 나옵니다. 지속 중인 급매는 리포트 본문에 있습니다.

### HTML 리포트 (reports 브랜치의 `reports/날짜.html`)
위에서부터:
1. **요약**: 상태, 조사 단지 수, 신규·인하·지속 건수, 실패 단지
2. **신규·가격 인하 급매**: 단지, 평형, 동·층, 가격, 기준가와 할인율, 근거, 네이버 매물 링크
3. **지속 중인 급매**
4. **지난주 급매 중 내려간 매물**: 매물이 사라졌거나 더는 급매가 아닌 것 (한 번만 표시)
5. **단지·평형별 현황**: 평형마다 일반층 실거래 중앙값(건수), 일반층·저층 매물 최저가, 매물 수
6. **경고·오류**: 국토부·네이버 실거래 차이, 수집 오류
7. 데이터 출처

용어:
- **실거래 부족**: 최근 24개월 일반층 실거래가 없어 매물끼리만 비교했습니다. 표본이 1~2건이면 "표본 부족"으로 표시합니다.
- **층 미상**: 층 표기를 해석할 수 없는 매물. 판정에서 빼고 따로 보여 줍니다. 링크로 직접 확인하세요.
- **근거**: "실거래" = 최근 일반층 실거래 중앙값보다 쌈, "매물" = 같은 평형 다른 일반층 매물 최저가보다 쌈.
- **중개사 n곳**: 같은 집을 여러 중개사가 올린 경우 하나로 묶고, 가장 싼 가격을 대표로 씁니다.

### 주의
- 실거래는 신고까지 최대 30일 정도 늦게 올라옵니다. 최근 시세 변화가 늦게 반영될 수 있습니다.
- 리포트는 판단을 돕는 참고 자료입니다. 매물 상태·가격은 반드시 중개사에게 직접 확인하세요.
- 문제가 생기면 [RUNBOOK.md](RUNBOOK.md)를 보세요.
