# 중복 매물 묶기

구현 위치: `app/domain/dedup.py`

## 1. dedup_key
```
dedup_key = f"{complex_no}|{area_key:.2f}|{norm(dong)}|{norm(floor_raw)}|{norm(direction)}"
norm(s) = (s or "").replace(" ", "").upper()
```
- `floor_raw`는 슬래시 뒤 전체 층수까지 포함한 원본(`3/25`)을 정규화해 쓴다. 같은 동·층이라도 전체 층수 표기가 다르면(데이터 오류) 다른 키가 되지만, 오탐보다는 미탐이 안전하므로 그대로 둔다.
- 이 키는 재알림 이력(alert_history)의 키로도 쓰인다. **형식을 바꾸면 이력이 끊기므로** 변경 시 Orchestrator 승인과 마이그레이션이 필요하다.

## 2. 묶는 방법 `dedup(listings) -> list[Listing]`
1. dedup_key로 그룹화
2. 그룹마다 **가격이 가장 낮은** 매물을 대표로. 가격이 같으면 `confirmed_at`이 최신인 것, 그래도 같으면 `article_no` 사전순 첫 번째 (결정적 결과)
3. 대표 매물의 `realtor_count` = 그룹 크기
4. 그룹 내 다른 가격 목록은 메타데이터(`alt_prices`)로 보관해 리포트에 "같은 매물 다른 호가: …"로 표시할 수 있게 한다

## 3. 주의
- 동·방향 정보가 모두 비어 있고 층이 `저/중/고`처럼 뭉뚱그려진 매물은 서로 다른 집인데 같은 키가 될 수 있다. 이 경우에도 그대로 묶되, 그룹 크기가 3 이상이고 가격 차이가 5% 이상이면 경고 로그를 남긴다.
- `UNKNOWN` 층 매물도 묶기는 똑같이 한다 (판정에서만 제외).

## 4. 테스트 케이스
| ID | 입력 | 기대 |
|---|---|---|
| D01 | 같은 키 3건 (100000, 98000, 98000) | 1건, 가격 98000, realtor_count=3 |
| D02 | 같은 동·층, 방향 다름 | 2건 |
| D03 | 동 `101동` vs `101 동` | 1건 (공백 정규화) |
| D04 | 같은 키, 같은 가격, confirmed_at 다름 | 최신 confirmed_at이 대표 |
| D05 | 동이 비어 있는 두 매물, 층 `저/15` 동일, 방향 동일 | 1건 (경고 조건 아니면 로그 없음) |
| D06 | area_key 84.97 vs 84.96 | 2건 |
