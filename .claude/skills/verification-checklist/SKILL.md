# 검증 체크리스트

모든 항목은 **코드 또는 실행 결과로 확인**한다. 구현자의 설명은 근거가 아니다.

## C0. 공통 (모든 모듈)
- C0-1 `pytest -q` 전체 통과, 실패·skip 사유 없음
- C0-2 테스트가 실제 외부 서비스를 호출하지 않음 (네트워크 차단 상태에서도 통과)
- C0-3 비밀값이 코드·fixture·로그·handoff 문서에 없음 (`grep -rE "serviceKey=|bot[0-9]+:|@gmail.com"` 등)
- C0-4 CLAUDE.md §5 스키마를 그대로 사용 (임의 필드 추가·변경 없음)
- C0-5 가격 비교에 float 사용 없음
- C0-6 실패를 빈 결과로 숨기는 코드 없음 (`except: return []` 류)
- C0-7 `docs/handoff/<agent>.md` 존재, 가정한 것과 한계가 적혀 있음

## C1. 골격 (web-infra 1단계)
- C1-1 디렉터리 구조가 CLAUDE.md §6과 일치
- C1-2 `models.py`가 §5와 필드·타입 일치
- C1-3 `.env.example`에 필요한 키 전부, `.env`는 gitignore

## C2. 정규화 (normalize.py)
- C2-1 floor-area-normalizer의 모든 표가 parametrize 테스트로 존재하고 통과
- C2-2 검증자 반례: `"저 / 15"`, `"고"`, `"15"`, `"B2"`, `"옥탑"` 을 직접 넣어 보고 명세대로인지 확인

## C3. 매물 수집
- C3-1 fixture가 실제 응답에서 나왔고 날짜가 기록됨
- C3-2 공급 119.0㎡ 초과 평형이 제외되고, 이하 평형은 빠짐없이 포함
- C3-3 페이지네이션 끝까지 수집 (2페이지 이상 fixture로 테스트)
- C3-4 요청 간 대기·순차 실행이 코드에 있음, 401/403/429/HTML 응답 시 `blocked` 예외
- C3-5 listing-dedup 테스트 D01~D06 통과

## C4. 실거래 수집
- C4-1 25개월 조회, 페이지네이션, (LAWD_CD, 월) 캐시
- C4-2 해제 거래가 `cancelled=True`로 남아 있음 (버리지 않음)
- C4-3 단지 식별이 저장된 식별자 기반이며, 후보 0개/복수일 때 자동 확정하지 않음
- C4-4 ±0.5㎡ 매칭, 36평 초과 거래는 경고 없이 제외
- C4-5 교차검증 경고 3종이 테스트됨

## C5. 급매 판정 (가장 엄격히)
- C5-1 bargain-rules §6의 R01~R21이 **모두**, 기대값 **그대로** 테스트에 있음 (하나라도 빠지거나 기대값이 바뀌면 반려)
- C5-2 `rules.py`에 I/O·현재 시각 호출 없음
- C5-3 검증자 반례 직접 실행:
  - 같은 계약일 거래 3건의 정렬이 결정적인지 (실행 순서를 섞어 10회 실행해 같은 결과)
  - NORMAL 매물이 1건뿐이고 실거래도 없을 때 급매가 아님
  - LOW 매물만 있고 NORMAL 매물·실거래가 모두 없을 때 급매가 아님
- C5-4 reasons 순서, discount_pct 계산이 명세대로

## C6. 알림·리포트
- C6-1 재알림 분류 표(notify 스킬 §2) 모든 행이 테스트됨
- C6-2 수집 실패 단지의 이력이 변경되지 않음
- C6-3 발송 실패 시 이력이 커밋되지 않음
- C6-4 텔레그램 4096자 분할, 실패 알림 별도 메시지
- C6-5 이메일 샘플에 요약·급매·현황·경고 섹션이 순서대로 있고, "실거래 부족"·"층 미상"·"수집 실패"가 보임
- C6-6 판정 근거 문구가 bargain-rules §7과 일치

## C7. 웹·파이프라인·배포
- C7-1 인증 없이 웹 접근 불가, 인증 정보 없으면 기동 거부
- C7-2 단지 검색→등록→목록→삭제 흐름이 동작 (TestClient로 확인)
- C7-3 단지 하나가 예외를 던져도 나머지 단지 결과가 나오고 status=PARTIAL
- C7-4 서버 TZ=UTC 환경에서도 다음 실행 시각이 화요일 10:00 KST
- C7-5 중복 실행 락 동작
- C7-6 `docker compose up` 후 `/healthz` 200
- C7-7 USER_GUIDE, RUNBOOK 존재, RUNBOOK이 schedule-deploy §5 증상을 모두 다룸

## C8. 통합 리허설 (실데이터)
드라이런으로 실제 단지 1~2개를 1회 실행한 뒤:
- C8-1 평형 목록이 네이버 화면의 평형 탭과 일치 (36평 이하)
- C8-2 무작위 매물 5건을 네이버 화면과 대조: 가격, 동, 층, 면적 일치
- C8-3 평형 하나를 골라 일반층 실거래 3건과 중앙값을 국토부 실거래가 공개시스템 화면 또는 원본 응답과 손으로 대조
- C8-4 급매로 판정된 매물마다 계산을 손으로 재현 (기준가 × 95%/90%와 가격 비교)
- C8-5 급매가 0건이면, 각 평형에서 가장 싼 매물이 왜 급매가 아닌지 1건 이상 손으로 확인 (규칙이 아예 안 도는 버그 방지)
- C8-6 드라이런 텔레그램·이메일 출력 파일이 사람이 읽기에 자연스러운지 확인

C8 결과는 `docs/verification/integration_<날짜>.md`에 대조표로 남긴다.
